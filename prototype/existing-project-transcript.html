# Riverside Ticketing Internal support-ticket tracker. Express + EJS server-rendered views + jQuery for interactivity, SQLite via `better-sqlite3`. No test suite — verify manually against the seeded dev DB. ## Structure - All request handling lives in `routes.js` (1,200+ lines, no sub-routers). Don't split it as a side effect of an unrelated change — that refactor deserves its own PR. - Views: `views/tickets/*.ejs`, plain server-rendered HTML + jQuery, no client framework. ## Auth - `req.session.role` is `"admin"` or `"agent"`, checked inline in each handler — there's no auth middleware layer yet. - Ownership rule used throughout: agents see/act on tickets where `assignee_id = req.session.userId`; admins see/act on all tickets. Any new ticket-scoped route must respect this split. ## Data gotchas - `tickets.status` is a free-text column, not an enum or FK. Known values in practice: `open`, `pending`, `closed`, plus legacy rows with inconsistent casing (`Closed`, `CLOSED`). Always compare case-insensitively until/unless the column is migrated to an enum. ## Conventions - No CSV-writing utility exists yet — first one added should be a small, audited dependency, not hand-rolled escaping.
